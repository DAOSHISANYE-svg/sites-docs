# ADR-008 · 重工具链评估与取舍（Terraform / Pyrra-SLO / OpenAPI 契约框架 / 混沌测试）
> 2026-10-25。全网经验（CF 官方 IaC 文档、Terraform provider v5 三资源模式、Pyrra/slo-tracker、契约测试 CI 实践）对照后，**评估=考虑过，暂不引入**；理由证据化，升级路径保留。

## 决策
| 重工具 | 判定 | 理由（证据） | 升级触发 |
|---|---|---|---|
| **Terraform 管 CF 资源**（D1/KV/DO/Worker/Pages） | **暂缓** | ① CF token 无 D1/KV 读 scope（实测：活体 `/api/health` 200 仅能间接证 D1 在跑，dashboard 面受限）；`terraform plan` 需要 D1/KV/Workers 读权限 ② 规模=2 站 + 1 Worker + 1 D1，资源面小，`sites.manifest.yaml` 已机器可读在册 ③ 引入 tf 二进制 + 远端 state（R2）= 新依赖面 + 新失火点 | CF token 扩权（主人授权）后，以 provider v5 三资源模式（`cloudflare_worker` + `_version` + `_deployment`）施工 |
| **Pyrra / Prometheus 栈**（SLO 监控） | **不引入，改文件式 SLO** | 无 metrics 采集管道（CF 侧指标需 API 拉取，本地无 Prometheus）；规模=2 站点，Google SRE 式 burn-rate 用 **双日 guard 双探活 + `slo-ledger.jsonl` 台账 + 48h D1 备份新鲜度** 覆盖可用性面（ADR-006 exit0 约定） | 站群 >5 / 需要 P95 时延 SLO 时，再评估轻量 Prometheus 或 CF 侧 Metrics API 拉取 |
| **OpenAPI + Schemathesis 契约测试** | **暂缓，现有机制已覆盖面** | 双站 API=静态直发 Pages（零 build）+ 共享 Worker（`api-manifest.json` 58 exact + 7 prefix 已机器可读）；守卫已有 llms 死链 + 端点契约断言；全量响应 schema 校验=新 CI 依赖（schemathesis/pip 面） | 端点数 >100 或响应结构频繁变更时，以 `api-manifest.json` 为契约源接 schema 校验 |
| **混沌测试（故障注入）** | **不做**（本规模不匹配） | 双站=CF 托管，注入面=CF 控制面（不可控）+ Worker 版本回滚（已有）；收益 < 成本 | 出现 >2 次同源级故障后再评估 |

## 与已落地件的映射
- 可用性 SLO 面 = `slo-ledger.jsonl`（双日 9/21 guard 全绿时追加 `{ts,xmg,ymg,api}`；§13 `slo:ledger_fresh` 断言 ≤15h 新鲜）
- 数据完整性 = §13 `backup:d1_fresh`（`E:/hermes/d1-backups/*.sql` 最新 ≤48h；2026-10-25 实测当日双 sql 在档）
- 契约面 = `api-manifest.json` + §11 llms 死链 + §10 部署门禁存在性
- 事故面 = `RUNBOOK.md`（8 故障模式四段式 + 不可逆即报纪律）
